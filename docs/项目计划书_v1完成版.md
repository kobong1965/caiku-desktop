# 裁库 V1 项目计划书（完成版）

## 产品第一性原则

把原本散落在人工剪辑里的重复决策，固化成可追溯的本地素材流水线：原视频只读，派生素材按款号归档，低于 2 秒的片段永不进入可用库，成片必须通过技术规格与文案风险闸门后才能交付。

## V1 已交付范围

- Electron Windows 桌面外壳，启用上下文隔离、安全预加载桥和受控 IPC。
- FFprobe 读取视频轨道；FFmpeg 检测镜头、拆分、合并短边界、转码与封面生成。
- 款号/日期/批次目录与 13 类业务目录，持续写入 `manifest.json`。
- 四个互联模块：原素材处理、素材管理、剪辑成片、脚本管理。
- 所有可添加资产都有删除入口；派生视频删除时进入 Windows 回收站，原视频不受影响。
- 固定输出 MP4、H.264、AAC 48 kHz、30 fps、1080×1920、9:16。
- 1–20 条批量混剪；支持本地配音、音乐和 Windows 离线语音兜底。
- 离线风险词、承诺性表达、价格稀缺性、脚本/素材分类覆盖和技术规格检查。
- 每条成片独立质检报告；阻断级文案风险不允许生成。

## 质量门槛

- `minimumClipSeconds = 2.0` 为不可覆盖常量。
- 原视频不覆盖、不移动；处理失败保留失败清单。
- 字幕策略结果统一进入人工抽检，复杂移动文字和主体重叠必须复核。
- 离线语义检查只做分类对齐；逐帧多模态与逐字 ASR 是后续云模型增强项，界面必须明确模式，不能伪装为云端 AI 结论。
- 千川投放前仍需人工确认商品资质、活动价格、库存和抖音实时规则。

## V1.1–V2 路线

1. V1.1：字幕框选编辑器、关键帧跟踪、任务取消/恢复、素材回收站。
2. V1.2：本地 ASR、口播逐字对齐、脚本版本历史、重复镜头检测。
3. V1.3：可配置多模态供应商，逐帧核对颜色、版型、动作与口播卖点。
4. V2：商品/款号批量选材、脚本模板、AI 配音、音乐策略、视频数量，自动生成差异化矩阵并输出投放回传数据。

## 数据与发布策略

用户素材、脚本和报告默认只保存在本机。普通更新只增加补丁版本，安装目录、桌面快捷方式和用户数据目录保持不变。打包产物只留在本机；没有当次明确授权时不上传 GitHub 或第三方平台。
