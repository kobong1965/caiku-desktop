# Spec: 剪辑智能体训练系统 v0.1（已确认）

## 已确认产品决策

1. 目标用户是中国抖音服装带货团队，第一阶段优先西裤、长裤等裤装种草、测评和商品卡短视频。
2. 市场脚本学习只分析用户主动投喂的视频，例如从“还有人不懂西裤要怎么穿搭？”这类问题钩子中学习剪辑结构、镜头顺序和剪辑手法；智能体不联网搜索或下载市场视频，也不复制第三方完整文案。用户选择云端千问时，允许把已投喂视频的分析帧发送到已配置模型端点。
3. 固定工作流是：读取素材分类板块已由人工确认的款号分类清单 → 理解脚本每句话 → 从对应分类中选择细节、穿搭、整体、动作等画面 → 生成连贯时间线 → 生成配音与字幕 → 通过逻辑门禁后输出。
4. 同时支持两种训练数据：只有参考成品；原素材 + 成品 + 脚本/口播 + 音乐 + 时间线的成对案例。
5. “训练”第一阶段指案例记忆、特征提取、相似案例检索、剪辑决策复用和用户反馈学习，不直接修改大模型权重。
6. 大文件保存在用户素材盘，软件只保存索引、特征、缩略图和分析结果。
7. 训练入口放在“脚本管理”的“市场脚本学习”中；日常生成仍从“素材混剪”的 AI 编排进入，不新增主导航。
8. 当前版本不读取、不依赖、不显示千川投放数据或千川评分；只使用人工接受/拒绝、1–5 分和修改原因作为学习信号。

## Objective

建立一个可持续投喂、可校正、可回滚、可量化验收的服装带货剪辑智能体。它不是单次让大模型“随便剪”，而是学会以下决策：

- 什么镜头适合做前 3 秒钩子。
- 什么镜头能直接证明口播中的卖点。
- 人物穿搭、整体展示、细节讲解、动作证据和测评对比如何排序。
- 每个镜头用多少秒，在哪里切，如何跟口播、字幕和音乐节拍对齐。
- 什么是好案例、坏案例，用户改了什么，下次如何少犯同类错误。
- 在商品证据不足、字幕残留、镜头重复、构图破坏或平台风险时拒绝生成。

### 三项核心能力

1. **会看素材分类清单**：读取当前款号在素材盘中已经由“素材分类”板块和人工确认好的分类，知道每个分类下有哪些片段；不重新检测、不二次筛选、不改变分类结果。
2. **会按脚本剪辑**：先理解脚本结构和每句话的画面意图，再从对应素材分类中选择片段，不能先随机选镜头再硬套文案。
3. **会讲完整逻辑**：配音、字幕和镜头共用同一份逐句时间线；主题、卖点和结论必须连续，不能前后跳题、重复结论或出现无画面证据的口播。

### 板块责任边界

| 板块 | 负责 | 不负责 |
|---|---|---|
| 素材分类 | 分析、拆分、去字幕、静音、分类，并由人工完成筛选和确认 | 不决定最终脚本与成片顺序 |
| 素材管理 | 按款号和二级分类保存、展示人工确认后的素材 | 不学习剪辑方法 |
| 市场脚本学习 | 分析用户主动上传的参考视频，提取钩子、镜头顺序、切点、节奏、字幕、口播和剪辑手法 | 不联网搜索、不自动抓取或下载市场视频 |
| 剪辑智能体 | 读取已确认的分类清单，按脚本从分类中选材并生成逻辑时间线 | 不二次筛选素材、不删除素材、不修改人工分类 |

### 市场脚本模式合同

```js
{
  patternId: "question-hook-detail-outfit",
  hook: {
    type: "question",
    template: "还有人不懂{product}要怎么{goal}？",
    targetSeconds: [0, 3]
  },
  narrativeOrder: [
    "question_hook",
    "detail_evidence",
    "outfit_result",
    "use_case",
    "soft_cta"
  ],
  requiredMaterialRoles: ["detail", "outfit", "overall"],
  continuityRules: [
    "同一款号",
    "每句有画面证据",
    "下一段承接上一段结论"
  ],
  voiceStyle: "real-review-short",
  subtitlePolicy: "voice_text_aligned"
}
```

成功不以“导入了多少视频”衡量，而以看不见的测试集上的选镜、切点、画文对应、节奏和人工偏好结果衡量。

### 已确认素材分类清单合同

```js
{
  sku: "918",
  source: "material_classification_manifest",
  humanConfirmed: true,
  categories: {
    detail: [{ materialId: "detail-001", path: "D:/.../detail-001.mp4" }],
    outfit: [{ materialId: "outfit-001", path: "D:/.../outfit-001.mp4" }],
    overall: [{ materialId: "overall-001", path: "D:/.../overall-001.mp4" }],
    action: []
  }
}
```

该清单是剪辑智能体唯一的素材输入真相源。智能体可以依据脚本选择分类和片段，但不得运行字幕检测、质量评分、款号判断或其他二次过滤，也不得从清单中删除素材。

### 投喂层级

| 层级 | 需要的文件 | 可学内容 | 建议数量 |
|---|---|---|---:|
| A 级成对案例 | 原素材 + 成品 + 脚本 + 音频 + 时间线 + 评价 | 选镜、切点、排序、画文对应、节奏 | 首批 20–30，稳定 100+ |
| B 级参考成品 | 成品 + 文字脚本/转写 + 好坏标签 | 钩子、结构、口播风格、字幕密度、节奏 | 首批 50–100，稳定 300+ |
| C 级反例 | 低分成品 + 失败原因 | 不能使用的选镜、AI 腔、重复、模糊、画文错位 | 首批 20+，持续累积 |

千川反馈不在当前版本范围内；即使历史数据已经存在，也不得传入当前剪辑智能体或影响剪辑决策。

## Learning Stages

1. **V1 案例记忆与检索**：视频分析后产生剪辑配方，根据款号、类目、镜头角色、脚本意图和风格检索相似案例。
2. **V2 决策排序学习**：当用户累积 100+ 个高质量成对案例和接受/拒绝反馈后，训练轻量选镜与切点排序器。
3. **V3 可选微调**：只在 500+ 个经人工验收的成对案例、独立验证集和明确回滚方案齐备时评估，且需用户另行确认。

## Tech Stack

- Windows 本地桌面应用：Electron 43.4 + CommonJS。
- 现有剪辑决策：`ai-editor-service.cjs` + `timeline-optimizer-service.cjs`。
- 视觉分析：现有千问/本地 Qwen 路由，结果统一写入素材能力卡。
- 素材输入：直接读取“素材分类”板块保存且经人工确认的分类 manifest，不在剪辑智能体内重复分析。
- 案例索引：第一版使用本地 JSONL + 可重建特征索引，不引入远程数据库。
- 原始视频、成品和音频仅保存绝对路径与哈希，不默认重复复制。

## Code Style

延续现有 CommonJS、纯函数优先、有界输入和窄 IPC 风格：

```js
function acceptTrainingCase(value = {}) {
  const rating = Math.max(1, Math.min(5, Number(value.rating || 0)));
  const usable = value.rights?.userOwnedOrAuthorized === true
    && Boolean(value.finalVideo?.path)
    && rating >= 4;
  return { usable, rating, reasons: usable ? [] : ["缺少授权、成品或高质量评价"] };
}
```

- 所有输入先规范化，再写入本地库。
- 每个分析结果必须记录模型、提示词、规则和版本。
- 训练案例不得修改原文件；删除默认移入训练库回收站。

## Testing Strategy

### 单元测试

- 训练案例 schema 、路径、哈希、授权状态和删除逻辑。
- 切点、镜头角色、钩子、口播和音乐特征提取。
- 分类清单读取必须完整保留人工确认的素材 ID、路径和分类，不得自行排除或改类。
- 相似案例检索必须排除删除、低分、错款和未授权案例。
- 用户人工修改必须保存为新版本，不覆盖旧决策。
- 叙事连续性必须拦截跳题、重复结论、无画面证据文案和结构顺序倒置。
- 配音文本、屏幕字幕与逐句时间线必须来自同一文本源并保持一一对应。

### 集成测试

- 拖入 100 条成品时界面不阻塞，分析可暂停、继续、删除和重试。
- 参考成品分析能生成剪辑配方，并可编辑后标为金标。
- 市场脚本学习只分析用户主动拖入的视频；测试中禁止发起市场搜索、抓取、下载或自动发现请求。用户选择云端模型时只允许请求已配置的模型分析端点。
- 选款号、素材和脚本后，智能体能检索相似案例并给出可追溯的选镜理由。
- 固定脚本“问题钩子 → 细节证据 → 上身结果 → 使用场景 → 轻 CTA”能按顺序匹配素材并生成完整时间线。
- 新智能体必须继续通过《素材分类与字幕清理验收基线 v0.1.23》。

### 盲测集

- 固定 30 个不参与学习的测试任务。
- 人工不知道是旧剪辑器还是新智能体生成的计划。
- 评分选镜、切点、节奏、画文一致、种草自然度和可投放准备度。
- V1 验收目标：新智能体在至少 70% 的盲测中优于当前基线，且硬门槛回退为 0。

## Boundaries

### Always

- 原视频、已验收分类素材、脚本、用户设置和历史工程只读保留。
- 每个可添加的原素材、成品、脚本、配音、音乐、标签和评价都有删除入口。
- 案例、分析、反馈、模型和规则全部版本化。
- 剪辑智能体只读取素材分类板块经人工确认的分类清单，并完整保留上游提供的素材项；上游分类结果是唯一真相源。
- 训练导入、分析和学习必须可暂停、恢复、删除和重跑。

### Ask first

- 微调任何大模型或上传训练数据到第三方。
- 新增付费模型、远程数据库或大型系统依赖。
- 读取抖音/千川账号、接入千川评分、自动上传成品或自动发布。
- 批量复制训练视频或大规模迁移历史数据。

### Never

- 不把参考视频的商品事实当成当前款号的真实事实。
- 不用测试集、低分案例、错款案例或未授权数据做正向学习。
- 不联网搜索、抓取、下载或自动发现市场视频；市场脚本案例必须由用户主动投喂。
- 不在剪辑智能体内重新检测、筛选、删除或修改人工确认的素材分类。
- 不在没有独立验证前替换当前稳定剪辑器。
- 不覆盖用户原始时间线和人工改动记录。

## Success Criteria

1. 可批量拖入成品、原素材、脚本、配音和音乐，每项可单独删除。
2. 能将参考成品分解为可编辑的剪辑配方：钩子、镜头角色、切点、节奏、字幕、口播、音乐和 CTA。
3. 成对案例能还原成品时间线，并记录人工修正后的金标时间线。
4. 生成剪辑计划时显示引用了哪些用户投喂案例、学了什么剪辑思路，以及每句使用了哪个素材分类和片段。
5. 用户的接受、拒绝、换镜头、改切点和改文案会保存为可回放反馈。
6. 前一版、新版和人工金标可在盲测集中对比，并可一键回滚到上一稳定版本。
7. V1 在 30 个隔离测试任务中至少 70% 优于当前剪辑基线；素材分类、字幕清理、片段时长、构图和静音继续由上游素材分类板块负责，剪辑智能体不得二次筛选或修改其结果。
8. 有口播模式下，配音、字幕、逐句文案和对应镜头时间完全对齐；纯音乐模式允许没有口播和字幕。
9. 逻辑门禁能阻止跳题、重复结论、无素材证据文案和叙事顺序倒置进入渲染。
10. 当前剪辑计划、学习报告和验收界面不读取、不展示、不依赖千川指标。

## 已关闭问题

当前没有阻塞开发的问题。参考成品和成对案例都只由用户主动投喂；素材清单直接采用素材分类板块的人工确认结果；没有千川数据时，以接受/拒绝、1–5 分和修改原因为学习信号。
