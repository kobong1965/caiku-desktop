# 裁库全软件 UI 排版、字号与交互状态审计报告

- 审计日期：2026-08-21
- 审计对象：当前本机安装版“裁库 v0.1.9 · 本地素材工作台”
- 审计窗口：约 1440×945，Windows 桌面环境
- 审计方法：逐页实机走查、关键弹窗检查、代码侧页面/弹窗清单核对
- 综合健康度：**一般——产品结构已经成立，但存在 4 个会反复影响生产效率的系统性排版问题**
- 报告定位：本报告替代此前只覆盖两张截图的局部报告

## 一、结论先行

当前界面的问题不是“整体文字太大”。页面标题、模块标题和主要按钮的字号基本合适；真正的问题是：

1. **全局顶部偏移重复计算。** 自定义标题栏下方长期出现约 38px 的空白带，历史批次提示条还会被页头遮挡。
2. **长页面的滚动容器设计错误。** 页面向下滚动时，左侧品牌、上方页面标题和全局操作一起被卷走，用户失去当前位置和关键入口。
3. **核心生产表格/表单在桌面宽度下仍会崩。** 素材表的“预览/删除”和脚本段落的“删除段落”被压成竖排，属于必须优先修复的结构性问题。
4. **文字层级过细。** 代码中大量使用 9.2、10.35、11.5、12.65px 的小数字号。高密度工具可以紧凑，但业务正文、表单内容和高频操作不应低于 12px，输入内容建议统一为 14px。

产品已经具备可用的主流程和一致的黑白薄荷绿视觉语言，但尚未达到“长时间连续生产也稳定、快速、低误触”的桌面工作台质量。

## 三、跨页面系统性问题

| 优先级 | 问题 | 影响 | 建议 |
| --- | --- | --- | --- |
| P0 | 标题栏下方重复顶部偏移 | 所有页面首屏被压低，提示条被遮挡 | 自定义标题栏保留 38px；应用壳只补偿一次。`app-shell` 已有顶部外边距时，内部侧栏和页头的 `top` 应为 0 |
| P0 | 外层页面整体滚动 | 长页面下滚后丢失导航、页面标题、款号和主要操作 | 固定应用壳、侧栏与页头；只允许 `mainContent` 内部滚动；右侧检查器需要独立滚动时单独设容器 |
| P0 | 脚本段落与素材表格列宽崩溃 | 高频操作名称竖排，降低效率并增加误触 | 删除按钮固定最小宽度；表格动作列至少 112px；脚本卡改用明确的分组行，不依赖不稳定跨列 |
| P1 | 大量 9.2–11.5px 业务文字 | 长时间工作难读，125%/150% 缩放风险高 | 收敛到 12/14/16/20/24px；业务正文和表单内容 14px；帮助/标签不低于 12px |
| P1 | 空状态主按钮仍呈可用态 | 用户会点击无结果的修复、导出或添加动作 | 根据数据状态禁用并提供原因；按钮 disabled 时仍需达到可辨识对比度 |
| P1 | 危险操作样式与目标不统一 | 删除片段、删除段落、删除引用、删除音乐认知成本高 | 统一为最小 72×32px 的危险文字按钮；不可逆操作使用确认，尽量提供撤销 |
| P2 | 设置页内容过窄 | 1440px 下右侧大面积空白，信息密度失衡 | 内容宽度提升到 880–960px，或采用双栏设置卡；保留 24px 外边距 |
| P2 | 页面入口重复 | “上传新批次”“添加视频”等在页头和正文多次出现 | 保留一个全局快捷入口和一个上下文主入口，文案按当前页面变化 |

## 四、字号与间距建议

当前 CSS 中存在 9.20、10.35、11.50、12.65、13.80、14.95、16.10、17.25、19.55px 等大量小数档。它们没有给用户带来可感知的层级收益，却提高了维护成本。

建议统一为：

| 用途 | 字号 / 行高 | 建议字重 |
| --- | --- | --- |
| 页面主标题 | 24 / 32px | 700 |
| 模块标题 | 20 / 28px | 700 |
| 卡片标题、关键字段 | 16 / 24px | 600–700 |
| 正文、表单输入、按钮 | 14 / 22px | 400–600 |
| 字段标签、辅助说明、状态标签 | 12 / 18px | 500–600 |
| 左侧导航 | 15 / 22px | 600 |

间距与控件建议：

- 页面内容外边距：20–24px。
- 卡片内边距：16px；复杂编辑卡片可用 18px。
- 大分组间距：16px；字段间距：12px；标签与控件：6–8px。
- 常规按钮最小高度：36–40px；主要操作 42px。
- 危险文字按钮：至少 72×32px，不允许换行。
- 表格行高：至少 60px；动作列不允许被压缩成逐字竖排。

## 五、关键页面整改建议

### 5.1 脚本管理

将每个段落卡片固定为五层：

1. 段落编号、开始时间、删除按钮。
2. 时长、段落名称、目标素材。
3. 画面要求、屏幕字幕，两栏等高。
4. “本段需要口播”独立整行。
5. 口播文字、转场与节奏，两栏顶部对齐且都使用多行输入。

这项修改优先级高于单纯放大字体，因为当前首先是布局结构失稳。

### 5.2 素材管理

- 批次栏宽度从当前约 250px 提升到 280–320px，长名称最多两行并提供悬停完整提示。
- 固定“选择、缩略图、名称、类型、时长、使用次数、操作”的最小列宽。
- 操作列至少容纳两个横排按钮；窄窗口时允许表格横向滚动，但表头和行必须同步。
- 选材篮不要与筛选工具争抢同一行，可放到第二行右侧或做底部固定栏。

### 5.3 分类复核

- 不要通过整页降低透明度表达“待复核”；只对状态徽标使用黄色/灰色，素材缩略图保持正常对比度。
- 右侧检查器建议 340–380px，并保持独立滚动。
- “保存当前片段”保持主按钮；“标为不可用/删除片段”放在同一危险操作分组。
- 分类数量标签可横向滚动，但“全部/待复核”应固定在最前。

### 5.4 混剪与结果

- 素材选择器增加搜索、分类筛选、全选/清空；零选择时禁用“加入所选素材”。
- AI 编排状态文字、策略说明至少 12px；本地模型状态不要只依赖浅绿色。
- 零结果时禁用修复与导出；“生成数量”改成“计划生成数量”。
- “查看选材篮”实际会进入混剪流程，建议改名为“进入混剪”或“使用选材篮混剪”。

### 5.5 设置

- 设置导航固定在内容区左侧，主内容独立滚动。
- “强制启用”规则用锁定状态行，不使用 disabled checkbox。
- 固定导出规格若不可编辑，则移除“取消/保存设置”；若未来可编辑，再恢复表单与保存态。

## 六、基础无障碍风险

- 9.2–11.5px 的业务文字和状态标签对长时间办公及弱视用户不友好。
- 灰色帮助文字、禁用按钮、低透明度待复核卡片的对比度可能不足；需用实际颜色值测量 WCAG 4.5:1。
- 多处危险操作是很小的红色文字，点击目标未达到推荐尺寸。
- 必选规则使用禁用复选框，语义和视觉状态容易误解。
- 窗口控制按钮已有可访问名称，这是正向表现；但本轮未系统验证完整键盘焦点顺序、焦点可见性和屏幕阅读器朗读。

## 七、做得好的地方

- 黑、白、薄荷绿构成统一的品牌语言，适合专业生产工具。
- 五步混剪流程清楚，用户容易知道当前在哪一步、下一步做什么。
- 任务板、模型安全说明和发布前闸门都有明确业务价值，不是装饰性模块。
- 多数弹窗控制在一个主任务内，主次按钮关系清晰。
- AI 剪辑师的空状态解释了它读取什么、要做什么，产品心智比“机械自动剪辑”更接近用户真实需求。

## 八、证据边界

以下状态会写入项目数据、运行模型、上传文件或生成成片，本轮以审计为目的没有触发：

- 选择本地视频后出现的款号选择弹窗与真实上传完成态。
- 竞品视频分析、分析进度与结果落库。
- AI 剪辑师实际生成方案、方案确认、重新安排。
- 成片生成完成、AI 质检报告、修复与导出成功状态。
- 删除素材、删除片段、清空选材篮等破坏性确认流程。

代码侧已核对这些页面/弹窗入口存在，但未把未实测状态当成视觉通过项。

## 九、建议实施顺序与验收标准

### 第一批：阻断级排版修复

1. 修复 38px 重复顶部偏移。
2. 重构外层滚动容器，固定全局侧栏和页头。
3. 修复脚本段落卡片栅格和素材表格动作列。

验收：1440×900 与 1366×768 下无顶部空带、无竖排操作文字、长页滚动仍能看到导航和页面标题。

### 第二批：字号与状态统一

1. 统一为 12/14/16/20/24px 五档。
2. 危险操作统一尺寸、颜色、确认方式。
3. 修复空状态下错误的强可用按钮。

验收：业务输入内容不低于 14px，辅助信息不低于 12px；零数据/零选择时按钮状态与可执行性一致。

### 第三批：效率优化

1. 素材选择器增加搜索、筛选、全选。
2. 设置页提升内容宽度和分栏效率。
3. 统一“脚本/模板”“选材篮/进入混剪”等文案心智。

最终需在 Windows 100%、125%、150% 缩放，以及 1366×768、1440×900、1920×1080 三档窗口下复测。
