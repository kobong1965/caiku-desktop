# 裁库 UI 排版与字号审计报告

- 审计日期：2026-08-21
- 审计范围：素材混剪页、脚本管理编辑页
- 证据来源：用户提供的两张当前版本截图
- 审计方式：桌面端视觉层级、信息密度、表单可读性、控件对齐及基础无障碍检查

## 一、结论摘要

当前 UI 的基础设计语言已经成立，黑白主色、薄荷绿状态色、卡片与圆角控件整体一致，核心业务结构也容易理解。主要问题不是“所有文字都太大”，而是字号层级失衡：页面标题基本合适，脚本表单中的标签、输入内容、说明文字普遍偏小；同时存在两个明显的系统级排版问题。

1. 素材混剪页重复计算了标题栏顶部偏移，形成约一个标题栏高度的空白带，压缩了有效工作区。
2. 脚本段落的栅格结构失稳，“删除段落”被压成竖排，口播与转场字段高低不齐，影响扫描和操作。

综合判断：**界面可用，但尚未达到稳定的生产工具级排版质量。** 应先修复结构性问题，再统一字号和间距。

## 二、逐屏审计

### 屏幕 1：素材混剪页

健康度：**一般——主流程清晰，但顶部空间利用和局部信息层级需要整改。**

#### 主要问题

| 优先级 | 问题 | 截图证据 | 建议规格 |
| --- | --- | --- | --- |
| P0 | 标题栏下方出现大面积空白带 | 窗口标题栏与页面标题之间约有一个标题栏高度的纯白区域 | 标题栏高度固定为 38px；应用壳只保留一次 38px 偏移。若 `app-shell` 已设置顶部外边距，内部 sticky 侧栏和页头的 `top` 应改为 0 |
| P1 | 页面纵向内容整体下沉 | “素材混剪”、款号、素材盘等首屏核心内容被推低 | 修复重复偏移后，页头保持 64–72px，高度内垂直居中 |
| P1 | 字号层级过多且跨度不合理 | 主标题约 25px，但素材卡片说明、右侧质检元数据约 11.5–12px | 收敛为 12/14/16/20/24px 五档；正文和输入内容统一 14px，辅助说明不低于 12px |
| P2 | 左侧导航视觉重量偏大 | 16px 以上粗体导航与主内容标题竞争 | 导航建议 15px/22px、600 字重；选中态继续用黑底白字即可 |
| P2 | 素材卡片文字偏小 | 缩略图下的名称、时长、类型在高密度网格中不易扫读 | 卡片主标签 13–14px，元数据 12px，行高不低于 18px |
| P2 | 右侧质检栏较窄且信息密度高 | 310px 左右的侧栏容纳预览、标题和多项状态 | 可保持宽度，但将状态主文案设为 14px，副文案 12px，并保证每项至少 52px 高 |

#### 做得好的地方

- 页面主任务“素材—脚本—声音—AI 编排—结果”分步清楚。
- 主要按钮、次要按钮和危险操作已经有明显的视觉区分。
- 素材网格与右侧质检预览相邻，符合剪辑工作流的决策顺序。
- 黑白与薄荷绿的配色克制，适合高频桌面生产工具。

### 屏幕 2：脚本管理编辑页

健康度：**较差——信息架构合理，但表单栅格与字号已直接影响编辑效率。**

#### 主要问题

| 优先级 | 问题 | 截图证据 | 建议规格 |
| --- | --- | --- | --- |
| P0 | “删除段落”被压成逐字竖排 | 红框左下方四个字纵向排列，操作意图难以快速识别 | 将删除按钮固定到段落卡片右上角；最小宽度 72px、最小高度 32–36px，设置不换行，采用图标加文字 |
| P0 | 段落表单栅格发生错位 | 画面要求、屏幕字幕、口播文字与转场字段的列宽和高度不一致 | 将卡片拆成明确的 5 层：段落头、基础信息、画面/字幕、口播开关、口播/节奏；不要依赖跨列覆盖规则 |
| P1 | 表单标签和正文偏小 | 字段标签约 10px，输入和 textarea 内容约 11.5–12.5px | 标签 12–13px/18px；输入和 textarea 14px/22px；任何业务正文不低于 12px |
| P1 | 口播开关位置悬空 | “本段需要口播”夹在两组字段之间，垂直间距不足 | 设置独立整行，左右对齐，行高至少 36px，上下各保留 8–12px |
| P1 | 口播文字与转场字段不等高 | 左侧为多行文本框，右侧为单行输入，形成大片无效空白 | 两栏顶部对齐；建议两者都用最小高度 72px 的 textarea，或将转场单独放到下一行 |
| P2 | 段落卡片内部留白失衡 | 下半区有大面积空白，但字段之间又显得拥挤 | 卡片内边距 16px，分组间距 12px，标签与控件间距 6–8px；通过分组而非增加空白建立层级 |
| P2 | 破坏性操作位置不稳定 | 左侧脚本列表与段落卡片中的“删除”位置、形式不同 | 统一为右侧红色文字按钮或图标按钮，并保留确认/撤销机制 |

#### 做得好的地方

- 段落编号和开始时间形成了清晰的顺序锚点。
- “时长—段落名称—目标素材”的编辑逻辑符合剪辑脚本的认知顺序。
- 左侧脚本列表与右侧编辑区的主从关系明确。

## 三、推荐字号与间距基线

建议停用 10.35px、11.5px、12.65px 等过细的小数档位，统一成更容易维护的桌面端字体标尺。

| 用途 | 建议字号 / 行高 |
| --- | --- |
| 页面主标题 | 24px / 32px，700 |
| 模块标题 | 20px / 28px，700 |
| 卡片标题、重点字段 | 16px / 24px，600–700 |
| 正文、表单输入、按钮 | 14px / 22px，400–600 |
| 字段标签、辅助信息、徽标 | 12px / 18px，500–600 |
| 左侧导航 | 15px / 22px，600 |

间距建议：

- 页面主内容外边距：20–24px。
- 卡片内边距：16px。
- 大分组间距：16px。
- 字段之间：12px。
- 标签与控件：6–8px。
- 普通按钮最小高度：36–40px；关键按钮 42px。

## 四、建议的修复顺序

1. 先修标题栏重复偏移，恢复首屏有效高度。
2. 重构脚本段落卡片栅格，修复竖排删除按钮和字段错位。
3. 将脚本编辑区正文统一提升到 14px，字段标签提升到 12–13px。
4. 统一全局字体标尺、行高、表单高度和卡片间距。
5. 在 Windows 100%、125%、150% 缩放和 1366×768、1440×900、1920×1080 三档窗口下复测。

## 五、基础无障碍风险

- 当前 10–11.5px 的标签和内容对长时间办公、125% 缩放及视力较弱用户不友好。
- 竖排“删除段落”降低了操作名称可识别性，按钮触控面积也可能不足。
- 灰色辅助文字的实际对比度需要在代码中测量；截图无法确认是否达到 4.5:1。
- 键盘焦点顺序、焦点可见性、复选框语义标签和屏幕阅读器支持无法仅凭截图确认，需要交互测试。

## 六、验收标准

- 标题栏下方不再出现额外 38px 左右的空白区。
- 所有业务输入正文不小于 14px，辅助信息不小于 12px。
- “删除段落”在任何窗口宽度下保持横排，且点击区域至少 72×32px。
- 两个连续段落卡片的字段列线、标签基线和输入控件高度一致。
- Windows 125% 与 150% 缩放下无文字截断、重叠、竖排或横向滚动。
