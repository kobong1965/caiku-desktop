# 大模型视觉分类架构

## 模型职责

- 千问视觉模型：读取每个视频片段按时间顺序抽取的画面，返回素材分类、置信度、简短理由、标签和复核状态。
- DeepSeek：保留给后续脚本推理、文案一致性和风险词复核。当前不承担视频画面识别。
- 离线规则：只在用户主动开启“模型失败时允许离线兜底”后使用；结果必须标记为待人工复核。

## 分类流程

1. 本地 FFmpeg 进行镜头检测，并合并所有低于 2 秒的短片段。
2. 每个 2–9 秒片段按时间顺序抽取 3–8 帧，默认 4 帧。
3. 桌面主进程通过百炼 OpenAI 兼容接口调用千问视觉模型。
4. 模型只能返回固定分类：人物穿搭、整体展示、细节讲解、测评对比、动作展示、口播、其他。
5. 分类、置信度、理由、标签、模型名称和抽帧数写入 manifest；API Key 永不写入 manifest。
6. 低于设定阈值的片段进入人工复核；默认阈值为 85%。
7. 分类确定后再执行字幕处理和 1080×1920、9:16 统一导出，并保存到对应分类目录。

## 密钥安全

- API Key 只从设置页单向提交到 Electron 主进程。
- Windows 版本使用 Electron `safeStorage` 调用系统加密能力后保存。
- 渲染页面只能获得 `hasApiKey` 状态，无法读取已保存的明文密钥。
- 连接测试和正式分类都由主进程发起；渲染页面没有直接网络权限。

## 失败策略

- 默认：缺少密钥、鉴权失败、超时或模型返回无效分类时阻止批次继续，避免产生伪 AI 分类。
- 可选兜底：用户明确开启后，临时使用旧离线规则；manifest 写入 `offline_fallback`、失败原因和低置信度标记。
