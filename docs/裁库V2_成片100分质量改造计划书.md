# 裁库 V2：成片 100 分质量改造计划书

> 文档状态：已确认并完成本机 v0.1.13 实施  
> 编制日期：2026-08-22  
> 适用项目：裁库桌面版 0.1.11 之后的质量引擎升级  
> 目标用户：批量生产服装抖音带货视频、准备进入巨量千川测试的运营团队

## 1. 结论

裁库当前已经完成“能分类、能选材、能按脚本混剪、能导出 1080×1920、能生成质检报告”的基础生产链路，但还没有完成“只产出可投放成片”的闭环。

V2 的第一性原则是：

> 不能证明商品一致、不能证明画面与文案对应、原字幕未清理、存在平台风险、成片高度重复，任何一项不通过，都不得进入“可投放成片”。

本次所说的“100 分”分成两层：

1. **发布准备分 100**：软件能够在投放前客观检查的技术、内容、证据、字幕、声音、合规和差异化项目全部通过。
2. **真实投放表现分**：CTR、3 秒留存、完播率、点击转化率、CPA、ROI 等必须通过千川真实数据验证，软件不能在投放前承诺爆量或 ROI。

V2 必须做到：发布准备分未达到 100 的视频只进入“待修复”，只有 100 分成片才能进入“可投放”。

## 2. 当前样本基线

本轮以 2026-08-21 生成的三条“神裤测评 01”成片作为失败基线：

| 维度 | 当前水平 | 主要问题 |
|---|---:|---|
| 技术规格 | 94 | 格式正确，但仍需补齐黑帧、冻结、音画同步、安全区等检查 |
| 前 3 秒钩子 | 55–58 | 评论截图堆叠，缺少真人痛点和商品直接证据 |
| 商品展示 | 61–65 | 缺侧面、背面、腰头、褶皱和动态展示，且混入错误服装画面 |
| 节奏 | 49–53 | 45 秒偏长，15 秒平铺段拖沓，同镜头重复填时长 |
| 脚本—画面对齐 | 45 | 所有段落仅为间接证据，脚本要求与镜头不对应 |
| 字幕与口播 | 40–43 | 原视频烧录字幕残留，新口播与旧字幕冲突 |
| 转化结构 | 43–47 | 缺证明链路，结尾只有说明，没有有效行动指令 |
| 素材可信度 | 45–48 | 多账号、水印、遮脸、场景跳变，呈现搬运拼接感 |
| 合规 | 16–30 | 三条质检均为 blocked，可见评论含未经核实的效果和履约信息 |
| 差异化 | 20–25 | 三条音频完全一致，切点几乎一致，画面相似度 80.6%–90.3% |

当前最严重的软件缺陷是：**质检已经给出 blocked，视频仍被放入“成片”目录并显示混剪完成。**

## 3. 假设与范围

### 3.1 本计划采用的假设

1. 裁库继续是 Windows 本地桌面软件，现有安装位置、桌面快捷方式和用户素材数据必须延续。
2. `00_原视频`永不覆盖；字幕修复、裁切、静音和混剪只作用于派生素材。
3. 分类素材与最终时间线片段继续遵守“不低于 2 秒”的规则。
4. 千问视觉模型用于画面理解与成片复核，本地 Qwen/Ollama 用于剪辑计划；模型不可用时必须明确阻断，不能伪造“AI 已通过”。
5. 每个款号必须建立“目标商品资料卡”，至少包含商品参考图、品类、颜色、版型及允许宣传的信息。
6. V2 不自动发布到抖音或千川，只负责生成、质检、归档和导入投放数据。
7. 平台规则检查是发布前辅助筛查，不宣称法律认证，也不替代人工确认商品资质、库存、价格和履约信息。

### 3.2 本期不做

- 不自动创建千川计划或自动消耗广告预算。
- 不训练自有基础大模型。
- 不删除历史原片、历史脚本或历史成片。
- 不用单一模型分数直接替代确定性技术检查。

## 4. 100 分评分模型

每个维度内部按 100 分计算，再按权重汇总。以下硬门槛有任意一项失败，总分直接记为“未通过”，不得进入可投放目录。

| 维度 | 权重 | 达到维度 100 分的条件 | 硬门槛 |
|---|---:|---|:---:|
| 技术与导出 | 10 | 1080×1920、9:16、H.264、AAC 48kHz、30fps 容差内；无黑帧、冻结、花屏、音画错位；时长符合脚本 | 是 |
| 商品身份一致 | 15 | 时间线中 100% 镜头与目标款号、品类、颜色相符；不得出现短裤、牛仔裤或其他款号 | 是 |
| 脚本与直接证据 | 15 | 每个口播主张都有直接画面证据；`missing`、`indirect`、不支持主张均为 0 | 是 |
| 前 3 秒钩子 | 10 | 0.5 秒内出现目标商品；3 秒内完成痛点、结果或对比，并有真人/商品证据；不能只用评论截图 | 否 |
| 节奏与镜头语法 | 10 | 总时长建议 20–30 秒；单镜头 2–4 秒；视觉变化间隔不超过 4 秒；无同片重复填充 | 否 |
| 商品证明完整度 | 10 | 按脚本覆盖整体、正侧背、腰头褶皱、面料、动态、搭配、尺码/人群等必需镜头 | 是 |
| 字幕与画面洁净度 | 8 | 原字幕、原账号、水印和评论风险文本残留为 0；新字幕完整、同步、在安全区、无遮挡 | 是 |
| 声音质量 | 7 | 素材原声为 0；人声清晰；响度建议 -16 至 -14 LUFS；峰值不高于 -1 dBTP；无爆音、断音 | 是 |
| 合规与真实性 | 10 | 口播、字幕、OCR 可见文字均无 block/review；价格、库存、发货、功效信息有实时依据 | 是 |
| 成片差异化 | 5 | 单片内不重复同一镜头；多成片的钩子、主体镜头、口播/BGM、CTA 有明确差异；相似度低于阈值 | 是 |

### 4.1 状态定义

- `ready_100`：所有硬门槛通过，十个维度均达到配置标准，进入“成片/可投放”。
- `repair_required`：无重大合规阻断，但存在可自动修复问题，进入“成片/待修复”。
- `blocked`：商品错误、合规风险、证据缺失、模型不可用等重大问题，禁止投放。
- `manual_review`：模型低置信度或商品资料不足，必须人工确认。

用户可以导出“待复核样片”用于内部查看，但不能把它标记为“可投放”。

## 5. 从低分到 100 分的功能改造

### 5.1 技术规格：94 → 100

新增确定性技术检测：

- ffprobe 校验分辨率、比例、编码、采样率、帧率、时长和音轨。
- FFmpeg 检测黑帧、冻结帧、花屏倾向、静音异常、爆音和音画时长差。
- 检测字幕是否越过抖音 UI 安全区。
- 导出后再检查一次，不能只检查导出参数。

验收：任一技术项失败时不生成 `ready_100`。

### 5.2 前 3 秒钩子：58 → 100

新增“钩子策略”而不是随机选择开头：

- 痛点型：身材/穿搭痛点 + 目标商品真人画面。
- 结果型：先展示上身效果，再解释版型。
- 对比型：只允许真实、同条件、可验证的前后或版型对比。
- 细节型：腰头、双褶、垂感近景直接开场。

规则：0.5 秒内必须识别到目标商品；前 3 秒不得只有评论截图、商城截图或与商品无关的人物。

### 5.3 商品展示：65 → 100

为每个款号新增“目标商品资料卡”：

- 3–8 张参考图：正面、侧面、背面、细节、颜色。
- 商品标题、类目、款号、颜色、版型、面料、适用人群。
- 允许宣传的事实与必须人工核实的信息。

分类后为每个素材生成：

- `productMatchScore`：与目标商品的一致性分数。
- `productIdentityStatus`：match / mismatch / uncertain。
- `visualEvidence`：整体、正面、侧面、背面、腰头、褶皱、面料、走动、坐下、转身等。
- `wrongProductReason`：错误品类、错误颜色、错误款号或主体不清。

规则：mismatch 永不进入时间线；uncertain 必须复核。

### 5.4 节奏：53 → 100

剪辑计划从“填满时长”改为“受约束的镜头语法”：

- 最终建议时长 20–30 秒，可按脚本设置其他时长。
- 每个片段不少于 2 秒，通常不超过 4 秒。
- 同一素材在一条成片中默认只能使用一次。
- 禁止用同片反复截取填满脚本段落。
- 静态平铺连续不超过 4 秒，必须由细节变化或动态动作承接。
- 结尾不得直接复制开头。

### 5.5 脚本—画面对齐：45 → 100

新增“主张—证据合同”：

| 文案主张 | 必需画面证据 |
|---|---|
| 腰头和褶皱细节 | 腰头/褶皱近景，主体占画面足够比例 |
| 垂感 | 站立、走动或布料自然下垂动态 |
| 久坐不塌 | 同款商品的坐下、起身或久坐前后实拍 |
| 显高/显瘦 | 默认改写为主观版型观感；若保留，需要真实条件一致的证明与合规复核 |
| 多套搭配 | 至少两套不同上装且裤子为同一款 |
| 正侧背展示 | 明确的正面、侧面、背面镜头 |

只有 `direct` 证据可以通过。模型返回“未提供选镜理由”或 `indirect` 时不允许确认计划。

### 5.6 字幕与口播：43 → 100

把字幕处理拆成三次检查：

1. 分类前：OCR 定位原字幕、账号、水印和评论文字区域。
2. 修复后：再次 OCR，确认残留率达到门槛；失败则换用裁切重构、遮罩修复或弃用素材。
3. 成片后：检查新字幕是否完整、同步、无遮挡、无错别字、无风险词。

新字幕必须由脚本时间轴生成，不能继续依赖素材原字幕。原字幕存在时，该素材不得显示“字幕已完成”。

### 5.7 转化能力：47 → 100

脚本管理新增服装带货结构模板：

1. 钩子：具体痛点或结果。
2. 证据：整体版型。
3. 证明：腰头、褶皱、面料、动态动作。
4. 适配：身材、场景、搭配和尺码边界。
5. CTA：查看商品页、确认尺码颜色，不虚构库存或优惠。

软件在渲染前检查：每个卖点是否有证据、每个脚本段是否有镜头、结尾是否只有免责声明而没有行动引导。

### 5.8 素材可信度：48 → 100

- 检测并标记第三方账号、水印、表情遮脸、评论截图和多来源画风。
- 同一成片优先使用同一拍摄主体、同一环境或同一视觉风格。
- 评论截图默认不能作为核心证据；需要使用时必须来源明确、文案可验证并经过 OCR 合规检查。
- 错误商品、主体不清、过度压缩、严重遮挡的素材直接设为不可用。

### 5.9 合规：30 → 100

合规检测覆盖三条通道：

- 脚本文字：口播、字幕、CTA。
- 可见文字：OCR 检出的评论、商城截图、水印和原字幕。
- 画面语义：效果对比、用户证言、错误商品、功效暗示。

价格、库存、优惠和发货承诺必须绑定生成时的商品页快照及时间；没有依据就自动删除或改写。`blocked` 和 `review` 均不能进入 `ready_100`。

### 5.10 差异化：25 → 100

新增成片指纹：

- 视觉嵌入/感知相似度。
- 音频解码哈希。
- 切点时间签名。
- 素材 ID 顺序。
- 钩子类型、文案、音乐和 CTA 签名。

生成 N 条视频时必须先生成 N 个创意策略，再生成时间线。不能先做一条模板后只轮换一个片段。

建议默认约束：

- 两条成片不得使用完全相同的音频。
- 开头 3 秒素材不得相同。
- 同一素材顺序重合率不得超过 50%。
- 综合视觉相似度达到 0.75 以上时必须重生成；阈值允许在设置中调整。

## 6. 新的完整工作流

```text
选择款号 / 建立目标商品资料卡
  ↓
上传原视频
  ↓
镜头拆分（每段 ≥ 2 秒）
  ↓
画面识别 + OCR + 商品身份 + 动作/景别 + 质量指纹
  ↓
字幕/水印修复并二次检查
  ↓
素材管理：只允许 match + 可用 + 字幕通过的素材进入候选池
  ↓
选择脚本 / 音乐 / 配音 / 成片数量
  ↓
主张—证据预检
  ↓
为每条成片生成独立创意策略与受约束时间线
  ↓
渲染候选片到 .working/candidates
  ↓
成片后技术 + OCR + 画文 + 音频 + 合规 + 相似度复核
  ↓
不满 100 → 自动修复或进入待修复
  ↓
满 100 → 原子移动到 成片/可投放
  ↓
导入千川结果 → 反向更新钩子、镜头和脚本表现标签
```

## 7. 软件界面修改

### 7.1 素材分类

- 增加“目标商品资料卡”入口。
- 上传前显示款号、参考图、目标颜色和品类。
- 分析进度增加：商品识别、OCR、证据识别、字幕复检。
- 分析完成页按“可用 / 错误商品 / 字幕残留 / 低质量 / 待复核”筛选。

### 7.2 素材管理

每张素材卡增加：

- 商品匹配度与匹配状态。
- 景别、动作、可证明卖点。
- OCR 风险文字数量。
- 字幕残留状态。
- 已使用次数与重复风险。
- 删除按钮继续保留。

### 7.3 脚本管理

- 每段脚本必须配置“需要什么直接证据”。
- 文案旁显示“已证明 / 缺证据 / 需改写”。
- 一键删除不支持主张或生成诚实改写版本。
- 增加服装带货 20–30 秒模板和纯音乐模板。

### 7.4 素材混剪

- 增加“100 分质量模式”，默认开启。
- 生成前显示预计分、缺失镜头和不能证明的文案。
- 视频数量大于 1 时必须选择差异化策略：钩子、语气、BGM、CTA、镜头方案。
- 禁止确认含 `indirect`、`missing` 或重复填充的剪辑计划。

### 7.5 成片结果

分成三个明确区域：

- **可投放 100 分**：允许打开、导出、复制路径。
- **待修复**：显示准确时间点、原因和“一键修复”。
- **已阻断**：显示错误商品、合规或模型问题，只允许查看报告和重新生成。

不能再使用“成功 3 条”概括 blocked 视频；必须显示“生成 3 条，100 分 0 条，待修复/阻断 3 条”。

## 8. 技术架构修改

### 8.1 新增服务

| 服务 | 职责 |
|---|---|
| `product-profile-service.cjs` | 保存目标商品资料卡、参考图和允许主张 |
| `material-intelligence-service.cjs` | 汇总视觉分类、OCR、商品匹配、动作景别和质量信息 |
| `claim-evidence-service.cjs` | 将脚本主张映射为必须出现的直接证据 |
| `timeline-optimizer-service.cjs` | 约束时长、镜头角色、重复和素材覆盖 |
| `caption-verification-service.cjs` | 修复前后 OCR 对比、字幕残留与水印复核 |
| `variant-similarity-service.cjs` | 视觉、音频、切点和素材顺序相似度 |
| `quality-score-service.cjs` | 统一十维评分、硬门槛和状态决策 |
| `repair-planner-service.cjs` | 把质检问题转成换镜头、改文案、重做字幕、重混音等修复动作 |

### 8.2 修改现有服务

- `ai-classifier.cjs`：输出商品身份、动作、景别、OCR 和直接证据；拒绝未知类别。
- `ai-editor-service.cjs`：禁止间接证据计划、禁止重复填充，要求每段给出可核验选镜理由。
- `quality-audit-service.cjs`：从单次视觉检查升级为多检查器聚合与修复循环。
- `compliance-engine.cjs`：同时检查脚本、OCR、ASR 和商品快照；规则版本化。
- `video-engine.cjs`：补充黑帧、冻结、音画时长、字幕残留检测。
- `mix-engine.cjs`：按独立创意策略生成变体，候选片先写入 `.working`。
- `workspace-service.cjs`：扩充 manifest 字段，并把输出划分为可投放/待修复/阻断。
- `desktop-bridge.js`、`app.js`、`index.html`、`styles.css`：实现质量工作台和修复交互。

## 9. 自动修复策略

| 问题 | 自动处理 |
|---|---|
| 错误商品 | 从时间线删除并从同角色素材池补位 |
| 原字幕残留 | 换字幕模式重新导出；仍失败则弃用素材 |
| 证据缺失 | 搜索直接证据；没有则诚实改写文案 |
| 同片重复 | 从同角色候选池换镜头，禁止再次使用同 ID |
| 成片太长 | 优先删除重复/低信息镜头，不机械加速 |
| 三条过度相似 | 重做钩子、镜头池、口播/BGM 和 CTA |
| 音频不达标 | 重做响度归一、重新配音或更换音乐 |
| 合规风险 | 删除风险可见文字、改写文案；无可靠处理时阻断 |

自动修复最多三轮。三轮后仍未达到 100，转人工复核，不无限循环消耗模型额度。

## 10. 千川数据反馈闭环

第一阶段只做 CSV 导入，不直接操作广告账户：

- 每条成片生成稳定的 `creativeId`。
- 导入曝光、3 秒播放率、5 秒播放率、完播率、CTR、CVR、CPA、成交额、ROI。
- 把表现回写到钩子类型、镜头角色、脚本句式、时长、音乐和 CTA 标签。
- 形成“款号内赢家”和“跨款通用策略”，不把单次偶然结果当成永久规则。

软件展示两类分数：

- 发布准备分：是否达到 100。
- 真实投放分：根据账号自己的历史基准进行百分位评分。

## 13. 边界

### 必须始终做到

- 保留原视频、历史数据、脚本、设置和素材引用。
- 每一个阻断都给出原因、时间点和可执行修复建议。
- 所有添加的素材、脚本、音乐、配音和输出继续提供删除入口。
- 每次改动运行语法检查、自动测试和桌面实机验收。
- 规则和模型版本写入报告，保证结果可追溯。

### 需要先确认

- 增加收费云模型或新增外部依赖。
- 自动读取千川账户或上传视频到第三方。
- 大规模迁移历史 manifest 数据结构。
- 允许人工绕过硬阻断并标记为可投放。

### 永远不能做

- 覆盖或删除 `00_原视频`。
- 把 blocked/review 输出冒充为 100 分成片。
- 模型失败时伪造 AI 通过结果。
- 把平台筛查描述为法律认证或保证投放通过。
- 在没有商品依据时生成价格、库存、优惠、发货或效果保证。

## 14. 成功标准

V2 完成必须同时满足：

1. 三条历史低分样本均被正确阻断，且不能进入“可投放”。
2. 错误商品画面识别率在金标测试集中达到 100%，不确定样本进入人工复核。
3. 直接证据覆盖率达到 100%，无 `indirect` 或 `missing` 计划可确认。
4. 原字幕、水印和风险文字残留未通过时，素材不得参与混剪。
5. 一条成片内部无同素材重复填充。
6. 三条成片的音频、开头和时间线不能完全相同，综合相似度低于配置阈值。
7. blocked 视频只进入“待修复/阻断”，100 分视频才进入“可投放”。
8. 输出继续满足 1080×1920、9:16、H.264、AAC 48kHz。
9. 原视频、用户状态、桌面快捷方式和已安装数据完整保留。
10. 全部语法检查、自动测试、打包和桌面验收通过。
