# 服装视频分析标准 v0.1.20

## 目标

把 2026-08-22 老钱风西裤 8 条样片已验收的方法固化到裁库批处理：原片保持不变，先判断哪些片段需要修复，再对普通硬字幕做逐帧 LaMa 修复；复杂图文不冒险涂抹主体，自动进入低复用待复核；通过终检的片段按服装画面语义写入素材盘。

## 已确认的基准结果

- 输入：8 条原视频；原文件大小与哈希不改变。
- 清洁母版：8 条，H.264、1080×1920、30fps。
- 可复用片段：37 条，全部不低于 2 秒。
- 低复用待复核：17 条，原因是截图、贴纸、放大镜、商品卡、拼贴或大面积营销文字等复杂覆盖层。
- 分类：人物穿搭 17、整体展示 4、细节讲解 7、动作展示 5、上衣相关 4。
- 终检：按 4fps 抽检 506 帧；自动疑似 2 帧经人工复核均为裤装高光/纹理误报，确认残留硬字幕 0 帧。

## 标准流水线

1. 归档原片：只复制，不转码、不覆盖、不删除。
2. 镜头检测：场景切分后把长镜头控制在 2–6 秒并合并短段；任何可复用输出片段时长不得低于 2 秒。
3. 多模态理解：识别人物、商品、景别、动作、服装部位、可见文字、文字区域及商品身份；没有直接画面证据时不得猜测。
4. 字幕风险决策：
   - `clean`：未发现硬字幕或覆盖图文，直接保真导出。
   - `repair_standard_caption`：仅有常规白/黄描边字幕或小面积水印，允许逐帧修复。
   - `route_low_reuse`：截图、贴纸、价格卡、放大镜、抠图、拼贴、大面积文字，或修复区域可能覆盖人物/商品主体；保留原画并进入低复用待复核。
5. 安全修复：本机 OpenCV 检测动态文字蒙版，GPU 可用时使用 LaMa 修复；保持完整构图，不裁切、不放大、不拉伸。
6. 服装语义分类：人物穿搭、整体展示、细节讲解、动作展示、测评对比、口播、上衣相关和其他。分类依据实际可见画面，不按视频先后位置猜测。
7. 终检：修复后重新做视觉 OCR/区域识别；仍有字幕、修复引擎不可用或结果不确定时，不得进入可混剪素材，统一进入低复用待复核。
8. 记录：manifest 保存模型、修复引擎、风险原因、前后 OCR、终检状态、可混剪资格和各阶段统计。

## 模型与本机引擎分工

- 千问官方视觉模型：主要分类、商品同款核对、文字/复杂图文识别和语义标签。
- 本地 Qwen：云端失败时兜底分类，结果强制待复核；不能代替逐帧修复。
- OpenCV + LaMa：逐帧检测和修复普通硬字幕。优先 CUDA；无可用依赖时安全降级为低复用分流，绝不把未修片段标成已清洁。

## 文件与状态

- `00_原视频`：只读归档副本。
- 正常分类目录：只放终检通过的可复用片段。
- `98_低复用待复核`：复杂覆盖层、修复不可用、修复后残留或不确定的片段。
- `99_不可用`：低于 2 秒或无法读取的源视频。
- 批次状态显示：检测镜头、AI 分类、字幕风险判断、安全修复、4fps 终检、完成。

## 验收条件

- 单元测试覆盖三类字幕决策、复杂图文分流、上衣相关分类和安全降级。
- 现有测试全部通过，`npm run check` 通过。
- 对已验收的 8 条样片回归：8 条输入、37 条可复用、17 条低复用、最短片段 ≥2 秒、5 类数量与基准一致、确认硬字幕残留为 0。
- 更新不替换用户状态文件、项目、脚本、任务进度和素材引用。
