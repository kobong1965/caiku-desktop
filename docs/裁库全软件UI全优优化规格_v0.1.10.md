# Spec：裁库全软件 UI “全部为优”优化

- 目标版本：拟定 `0.1.10`，实施前保持 `0.1.9`
- 基线报告：`docs/audits/2026-08-21-裁库全软件UI审计报告.md`
- 当前状态：规格与计划待确认，尚未实施

## Assumptions

1. 本轮只优化 UI 框架、排版、字号、状态反馈、操作效率和无障碍，不改变素材分析、AI 编排、混剪、存储等业务规则。
2. “全部为优”指基线报告中的 25 个页面/状态全部通过本规格的优秀级门槛，不以“看起来差不多”作为验收。
3. 保留当前黑白与薄荷绿设计语言，不重新设计品牌风格。
4. 更新必须原位完成，保留安装位置、桌面快捷方式、素材库、批次、脚本、混剪工程、任务状态、模型设置和本地路径引用。
5. 实施开始前由用户确认本规格和 `tasks/plan.md`。

## Objective

把裁库从“流程可用但排版不稳定”提升为可以长时间连续工作的专业桌面生产工具。所有主要页面、关键弹窗、空状态、禁用状态、长内容状态和滚动状态均达到统一的“优”级标准。

### 核心用户

- 高频整理、分类和复核视频素材的运营人员。
- 使用脚本、素材与本地 AI 剪辑师批量生成带货视频的剪辑人员。
- 需要在一套本地桌面软件内完成素材到成片闭环的管理人员。

### “优”级定义

单个页面只有同时满足以下条件才可标记为“优”：

1. 没有遮挡、重叠、异常竖排、意外横向滚动或内容被固定区域覆盖。
2. 页面标题、全局导航和关键上下文在滚动后仍可定位。
3. 正文与输入内容不低于 14px；标签、帮助和状态文字不低于 12px。
4. 主次按钮状态与真实可执行性一致；零数据、零选择和锁定状态不会伪装成可点击。
5. 危险操作横排、可识别、点击区域不少于 72×32px，并具备确认或撤销。
6. 键盘可到达所有可操作控件，焦点清晰，文本与背景对比度达到 WCAG AA。
7. 1366×768、1440×900、1920×1080 及 Windows 100%、125%、150% 缩放均通过实机复测。
8. 该页面的当前截图与审计基线对比后，没有新增可见回归。

## Code Style

统一使用语义化设计令牌和可复用组件类，禁止继续新增零散小数字号。

```css
:root {
  --font-label: 12px;
  --font-body: 14px;
  --font-nav: 15px;
  --font-card-title: 16px;
  --font-section-title: 20px;
  --font-page-title: 24px;
  --control-height: 40px;
}

.danger-action {
  min-width: 72px;
  min-height: 32px;
  white-space: nowrap;
}
```

约定：

- CSS 类名继续使用小写短横线形式。
- JS 状态更新保持“数据决定 UI”，不通过纯样式伪造可用状态。
- 同类组件必须复用同一个按钮、状态、表单和弹窗规则。
- 不为单个截图增加一次性像素补丁；优先修复布局容器和组件约束。

## Testing Strategy

### 1. 静态与合同测试

- `npm run check` 必须通过。
- `npm test` 必须全部通过，不允许删除或跳过现有测试换取绿色结果。
- 为全局壳、禁用状态、脚本段落、素材操作列和固定导出设置增加 UI 合同测试。

### 2. 桌面实机测试

- 逐项复测基线报告的 25 个页面/状态。
- 每个页面至少保存一张最终截图；长页面同时保存顶部和滚动后截图。
- 检查窗口最小化、最大化、关闭、侧栏切换、页内滚动、弹窗关闭和键盘 Tab 顺序。

### 3. 视觉回归矩阵

| 窗口 | 100% | 125% | 150% |
| --- | --- | --- | --- |
| 1366×768 | 必测 | 必测 | 必测 |
| 1440×900 | 必测 | 必测 | 必测 |
| 1920×1080 | 必测 | 必测 | 必测 |

### 4. 数据连续性

- 优化前记录当前款号、素材数量、脚本数量、任务统计、混剪工程和设置快照。
- 原位更新后重新核对，不允许出现清空、重置、路径丢失或被当成全新安装。

## Boundaries

### Always

- 先修全局壳和设计令牌，再修页面级问题。
- 每个任务完成后运行相关测试并保存实机截图。
- 保留用户现有数据、安装位置、快捷方式和本地路径引用。
- 任何按钮状态必须和真实可执行状态一致。
- 只对实际检查通过的页面标记“优”。

### Ask First

- 改变素材库目录结构或数据格式。
- 添加新的第三方 UI 依赖。
- 改变现有业务流程、AI 参数或输出规格。
- 删除已有兼容样式或迁移历史数据。

### Never

- 用清空数据、重装或默认文件覆盖解决 UI 问题。
- 为通过测试而删除、跳过或弱化测试。
- 将密钥、用户素材路径或业务数据写入日志、截图或仓库。
- 未经当前对话明确授权上传 GitHub 发布产物。
- 在没有最终回归矩阵和数据连续性检查时宣布“全部为优”。

## Success Criteria

### 全局框架

- 标题栏只计算一次 38px 偏移；所有页面不再出现顶部空带。
- 历史批次提示完整可见，不被页头遮挡。
- 侧栏和页头保持定位；仅主内容区滚动。
- 在 9 组窗口/缩放组合中无结构性溢出。

### 组件与字号

- 业务正文和表单内容统一为 14px 或更大。
- 标签、帮助、徽标和状态文字统一为 12px 或更大。
- 操作按钮不换行；普通控件高度 36–40px，主操作 42px。
- 所有危险操作满足最小尺寸、统一颜色和确认/撤销规则。

### 页面结果

- 基线报告 25 个页面/状态全部由“一般/较差”提升为“优”。
- 原本已经“良好”的页面同步升级到统一验收门槛，不发生回退。
- 所有空状态、加载态、禁用态、错误态与实际逻辑一致。

### 交付

- `npm run check`、`npm test` 全部通过。
- 生成新的完整 UI 验收报告和截图目录。
- 安装包构建成功，原位更新后数据、安装入口和快捷方式连续。
