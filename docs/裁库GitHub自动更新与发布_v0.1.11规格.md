# 裁库 GitHub 自动更新与发布规格 v0.1.11

## 1. 目标

为裁库增加可由用户主动控制的 Windows 更新流程，并把 0.1.11 的完整可运行软件与可审查源码发布到公开 GitHub 仓库。

## 2. 发布口径

- GitHub 仓库：`kobong1965/caiku-desktop`，公开可读。
- Release 标签：`v0.1.11`，必须为正式发布而不是草稿或预发布。
- Release 资产：`caiku-desktop-setup-0.1.11.exe`、便携版、安装包 blockmap、`latest.yml`、SHA256 清单。
- 源码仓库包含应用源码、测试、设计与产品文档、构建配置；排除用户素材、密钥、日志、缓存、构建产物和 `node_modules`。
- FFmpeg 二进制已包含在安装版和便携版中；由于单文件超过 GitHub 普通 Git 100 MB 限制，不直接提交源码仓库。

## 3. 用户流程

1. 用户进入“设置 > 软件更新”。
2. 页面显示当前版本、更新通道和发布来源。
3. 点击“检查更新”，软件从 GitHub Release 获取最新正式版本。
4. 没有新版本时显示“已是最新版本”。
5. 有新版本时显示版本号和发布日期，并启用“下载更新”。
6. 下载时显示百分比、已下载大小与下载速度，禁止重复检查和重复下载。
7. 下载完成后启用“安装并重启”；用户点击后退出软件并由 NSIS 完成原位更新。
8. 任何错误都留在更新页，允许重试，不阻断其他功能。

## 4. 技术约束

- 使用 `electron-updater` 与 electron-builder GitHub provider，不自行拼接下载地址。
- `autoDownload` 关闭，只有用户确认后下载。
- 关闭 `autoInstallOnAppQuit`，只有用户点击“安装并重启”后才调用安装。
- 只在 `app.isPackaged` 为真时联网检查；开发模式返回明确提示。
- 渲染进程只通过 preload 暴露的窄 IPC 调用更新功能。
- 主进程向渲染进程发送标准化状态：`idle`、`checking`、`available`、`latest`、`downloading`、`downloaded`、`error`。
- 更新安装不改变 `appId`、安装目录策略、快捷方式名称或 userData 路径。

## 5. 数据与安全

- 用户数据文件 `caiku-state.json` 不进入 GitHub，不进入安装包默认数据，也不会在更新中删除。
- API Key 仍只由 Windows 安全存储加密保存。
- 更新包通过 `latest.yml` 中的 SHA-512 元数据校验；发布时另生成 SHA256 清单供人工核验。
- GitHub Release 必须公开，否则客户端不得要求用户配置 GitHub Token。
- 不开启应用启动即自动下载，避免后台消耗带宽。

## 6. UI 验收

- 更新页在 1180×760 最小窗口下无横向溢出。
- 当前版本、最新版本、状态和主操作层级清楚。
- 下载进度使用原生可访问的 `progress` 元素并提供文字状态。
- 检查、下载、安装按钮只在对应状态可用；错误状态有重试入口。
- 设置页的固定信息页不显示无意义的“取消/保存设置”页脚。

## 7. 工程验收

- `npm run check` 通过，并包含更新服务语法检查。
- `npm test` 通过，并覆盖更新状态映射、IPC 边界和更新页 UI 合同。
- `npm run dist:win` 生成 0.1.11 安装版、便携版、blockmap 和 `latest.yml`。
- 0.1.11 原位安装后，原桌面快捷方式仍指向同一安装入口，用户状态文件哈希不变。
- GitHub 仓库可访问，`v0.1.11` Release 可访问，安装版直链可下载。

## 8. 非目标

- 本版本不实现后台强制更新、差异更新策略控制台或多渠道灰度发布。
- 本版本不为开发模式伪造线上更新结果。
- 本版本不把用户素材库、历史成片或本机设置上传到 GitHub。
