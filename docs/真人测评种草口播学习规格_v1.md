# Spec: 真人测评种草口播学习 v1

## 已采用的假设

1. 只学习两条参考视频的口播结构、节奏、停顿和语气，不克隆、冒充或复刻具体创作者的声纹。
2. “更像真人”不能只靠 TTS 提示词，脚本文字必须同步改成口语化、证据驱动的表达。
3. 短成片默认采用 20–35 秒的痛点种草结构；60 秒以上内容使用深度测评结构。
4. 商品主张必须来自款号资料卡和可见画面证据；参考视频中的具体卖点不能迁移到 918 款。
5. AI 生成的试听只算候选，用户人工试听通过前不得标记为 100 分或进入可投放目录。

## Objective

把两条本地参考视频提炼为原创的中文服装“真人测评种草”风格，应用到裁库的脚本和 Qwen 配音预设。目标用户是需要批量制作抖音服装带货视频的运营人员。

成功不是“声音更好听”，而是同时满足：开头像真人在说问题、正文跟画面讲证据、口语有快慢和呼吸、结尾克制引导，并且不出现播音腔、客服腔和机械匀速。

## Reference Findings

| 参考样本 | 时长 | 中文字数 | 平均语速 | 大于 180ms 的停顿 | 结构 |
|---|---:|---:|---:|---:|---|
| 不挑腿型短种草 | 36.25s | 154 | 4.25 字/秒 | 16 次，平均 331ms | 痛点提问 → 版型/面料/做工 → 多场景收口 |
| 鳞纹长裤深测评 | 136.37s | 552 | 4.05 字/秒 | 49 次，平均 373ms | 开箱立人设 → 版型 → 面料 → 做工实测 → 尺码上身 → 克制推荐 |

关键结论：上一版试听的平均语速并不是主要问题，机械感主要来自每句话力度相同、句尾相同、缺少口语连接词、没有“先观察再下结论”的过程。

## Style Contract

### 短种草模式（20–35 秒）

1. 0–4 秒：从腿型、搭配或购买犹豫切入，用一个问题或反差开场。
2. 4–20 秒：只讲 2–3 个可见证据，每个证据对应一个镜头，不堆形容词。
3. 20–30 秒：给出上学、通勤、日常等真实场景。
4. 最后 3–5 秒：使用“可以参考一下”“再看看尺码”等克制引导，不喊单。

### 深测评模式（60–120 秒）

1. 开场明确“先看实物/上身”，允许一句带判断色彩的提问。
2. 按版型、面料、做工、动作实测、尺码数据的顺序逐项验证。
3. 至少保留一处中性观察或小缺点，不能全程无条件夸赞。
4. 使用少量“你看、那、呢、OK、我觉得”等口语连接词，但每 1–2 句最多一个。
5. 每个结论必须能回指画面、尺寸或商品资料卡证据。

### 配音节奏

- 目标语速：3.8–4.3 个汉字/秒。
- 每 8–14 个汉字安排一次约 200–450ms 的自然呼吸；段落转折允许 500–900ms 停顿。
- 钩子略快，面料和尺码信息放慢；关键词加重，其余内容轻带过。
- 允许轻微思考感，不追求字字等长、句句圆满。
- 禁止新闻播报、客服话术、广告喊麦、全程高亢、机械匀速和统一句尾。

## Tech Stack

- Electron 43 + Node.js CommonJS
- Qwen3-TTS-Instruct Flash 指令配音
- 本地 Faster-Whisper small 仅用于参考音频离线转写
- Node.js `node:test` 自动测试

## Commands

- 离线转写：`python scripts/transcribe-reference-videos.py output/transcribe/reference-seeding <audio...>`
- 语法检查：`npm run check`
- 自动测试：`npm test`
- Windows 构建：`npm run dist:win`

## Project Structure

- `electron/services/qwen-tts-service.cjs`：真人种草配音预设和指令
- `electron/services/voice-style-service.cjs`：两种口播结构、脚本节奏检查与提示生成
- `electron/main.cjs`：脚本迁移和试听入口
- `prototype/v1/`：配音风格选择、试听和人工确认交互
- `tests/`：口播结构、配音指令、人工门禁测试
- `output/transcribe/reference-seeding/`：本地参考转写与时间戳，不随安装包分发

## Code Style

```js
const SHORT_SEEDING_STYLE = Object.freeze({
  id: "real-review-short",
  targetCharsPerSecond: [3.8, 4.3],
  requiredSections: ["pain_hook", "visible_evidence", "use_case", "soft_cta"]
});
```

- CommonJS 模块使用 `const`、纯函数和不可变常量。
- 预设使用稳定英文 ID，界面显示中文名称。
- 不把参考创作者姓名写进生产预设，避免形成模仿身份。

## Testing Strategy

- 单元测试：节奏区间、必备结构、禁止表达、配音指令和人工确认门禁。
- 集成测试：脚本选择 → Qwen 试听 → 人工确认 → 混剪。
- 人工验收：每个新预设至少试听一次，检查是否仍有统一句尾、匀速和喊单感。
- 回归测试：现有纯音乐模式、素材静音、画面不放大和硬字幕阻断规则保持不变。

## Boundaries

- Always：只使用商品证据；保留人工试听；保留完整画面；素材原声默认静音。
- Ask first：引入新的付费语音供应商、上传参考视频到第三方、改变默认成片时长。
- Never：克隆第三方创作者声纹；照搬完整文案；用违禁词或无法证明的功效；把未试听口播标为 100 分。

## Success Criteria

1. 新增“真人短种草”和“真人深测评”两个原创预设。
2. 短种草脚本包含痛点钩子、2–3 个画面证据、场景和克制 CTA。
3. 深测评脚本包含版型、面料/做工、动作或尺寸证据及至少一处中性观察。
4. Qwen 指令明确包含变速、自然呼吸、关键词重音、轻微思考感和不统一句尾。
5. 未试听确认的配音仍然被质量门禁阻断。
6. `npm run check` 和 `npm test` 全部通过。
7. 安装后保留原应用路径、桌面快捷方式、项目状态和本地素材引用。

## Open Questions

- 建议默认使用“真人短种草”，只有脚本目标时长达到 60 秒时才切换“真人深测评”。需要用户确认这个默认选择后进入生产代码实现。
